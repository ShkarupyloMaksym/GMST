# R5 — Eval and bench methodology

## Instructions

Review `eval/build_sets.py`, `eval/run_eval.py`, `src/gmst/bench.py` and `src/gmst/metrics.py` as the instruments that will pick the default model (`CLAUDE.md` "Model default is provisional"). Read first: root `CLAUDE.md`, `PLAN.md`, `review/checkpoint-1/PLAN.md` (rules 1–8), this file. Set `status: done` before starting.

Questions: (1) Are the WER numbers comparable to the `egorsmkv/speech-recognition-uk` leaderboard they are meant to reproduce (same test set, same normalization — casing, punctuation, apostrophes ʼ/'/’, numerals)? (5) Is `eval/results/` reproducible from the scripts (the onboarding lead on `tiny` vs `large-v3`)? ## Findings

- [blocking] The hypothesis cache is keyed by system name and clip id only, not by model, so `run_eval --gmst-model large-v3` silently resumes a cached `tiny` run and scores the mix as one system; no hyp record names its model — `eval/run_eval.py:273-284`, `scripts/R5/p3_cache_mixes_models.py`.
  Evidence: `done = {json.loads(x)["id"] for x in hp.read_text().splitlines() ...}` / `if m["id"] in done: continue` (run_eval.py:276, 283-284). Probe output: `records now in gmst-batch.jsonl: 18 | new decodes with large-v3: 6 | cached (tiny) records reused: 12` and `any record naming its model? False`. The only cached `gmst-batch.jsonl` today is a tiny run (its 4 en hyps score identical to `fw-tiny-*`: en WER 0.57 / CER 0.11 in all three), while the docstring says `gmst-batch FasterWhisperEngine(large-v3, ...)` (run_eval.py:6) and `--gmst-model` defaults to `large-v3` (run_eval.py:260). Answer to Q5: `scores.json` *is* reproducible from the cached hyps (`p1_rescore.py`: `rescore == scores.json: True` for all three systems), but which model produced `gmst-batch` is not recorded anywhere, and the next large-v3 run would be contaminated.
- [blocking] The default set sizes cannot separate the candidates at the leaderboard's gaps, and neither `run_eval` nor `bench` reports a confidence interval — `eval/build_sets.py:182` (`--per-lang` default 60), `src/gmst/bench.py:73-102` (one clip), `scripts/R5/p5_sample_size.py`.
  Evidence (clips needed, two-sided 95 %, 80 % power, corpus WER, cleaned-CV10 clips of 6.88 words, measured overdispersion phi = 1.90):
  `turbo-uk vs large-v2  0.97 pts: 5294 unpaired / 2893 paired (rho=0.45)`; `large-v2 vs large-v3 6.81: 132 / 73`; `large-v3 vs turbo 2.30: 1392 / 761`; `turbo-uk vs large-v3 7.78: 99 / 55`. 95 % CI half-width at WER 13.7 %: `n=4 ±17.7 pts`, `n=60 ±4.6`, `n=200 ±2.5`; bootstrap check on `small`, n=60: `[20.3, 29.6] around 24.7`. So 60 clips can at best separate {large-v2, turbo-uk} from {large-v3, turbo}; ordering within either pair needs ~800 (v3/turbo) to ~2900 (v2/turbo-uk, i.e. essentially all 3204 test clips — the leaderboard's own 1-point gap is at the edge of what that set can resolve). rho is from tiny vs small; two large-family models likely correlate more, so the paired numbers are an upper-ish bound. The n = 4 numbers in `scores.json` carry ±18-21 pts.
- [serious] `run_eval` reports the *mean of per-clip WER*, not corpus WER (total errors / total reference words), which is what the leaderboard and `jiwer.wer(list, list)` compute — so the numbers are not directly comparable to 13.72 / 20.53 / 22.83 / 12.75 — `eval/run_eval.py:210` (`_mean([_wer(m["text"], hyps[m["id"]]["text"]) for m in rows])`), `scripts/R5/p1_rescore.py`, `p5_sample_size.py`.
  Evidence: tiny-auto uk `macro=68.21 corpus=62.07`; en `macro=0.57 corpus=0.92`; on 60 clips tiny `corpus 55.69 % / macro 58.62 %`, small `24.70 % / 25.79 %`. A 1-3 pt bias is the size of the turbo-uk/large-v2 and large-v3/turbo gaps. Macro weighting also over-weights the short (4-5 word) clips.
- [serious] `real_cs` is empty and could never be non-empty: the cleaned CV10 labels contain no Latin script at all, and `run_eval` neither runs nor scores `real_cs` — `eval/build_sets.py:12-13,154-177`, `eval/run_eval.py:204,215,271`.
  Evidence: `latin rows 0` of 3204; the only non-Cyrillic characters in the labels are `{' ': 19602, "'": 163, '-': 82}`; `eval/results/data/real_cs.jsonl` is a single empty line (`real_cs manifest lines: ['']`). run_eval's sets are `{"en": "en", "uk": "uk", "mixed": None}` and `score()` iterates `("en", "uk")` and `("mixed", "mixed:inter", "mixed:intra")`. There is therefore no real code-switched audio anywhere in the harness; the docstring's "real embedded English (brand/product/person names)" does not exist in this corpus (the cleaning evidently transliterated or removed them).
- [serious] The raw faster-whisper baselines can never register a language switch, so `switch_detected` / `lid_recall` compare GMST against a baseline that is structurally zero — `eval/run_eval.py:70-71`, `p1_rescore.py`.
  Evidence: `"lang": getattr(s, "language", None) or info.language` — faster-whisper 1.2.1 `Segment fields: ['id', 'seek', 'start', 'end', 'text', 'tokens', 'avg_logprob', 'compression_ratio', 'no_speech_prob', 'words', 'temperature']` (no `language`), so every segment gets the file-level language; with two languages per clip `lid_recall` is capped at 50 % and `switch_detected` at 0. Also `fw-*-forced` on `mixed` is autodetect (`clip_lang` is `None` for mixed, run_eval.py:271), which is why its mixed rows in `scores.json` are identical to `fw-tiny-auto`'s. Per-language WER (run_eval.py:230-235) attributes hyp text by the *system's* label, so a segment labelled `ru`/`bg` (R2's lead) or the wrong one of en/uk is scored as 100 % deletion in its true language and vanishes: `wer_uk: 100.0` for all three systems in every mixed row — it measures LID x ASR jointly, not "per-language WER".
- [serious] The synthetic `mixed` clips do not measure what their names say — `eval/build_sets.py:118-142`, `scripts/R5/p2_mixed_construction.py`.
  Evidence: *intra*: audio is cut at `len(a["wav"]) // 2` samples but the reference at `len(w) // 2` words (build_sets.py:133-136); tiny word timestamps show `clips where a word straddles the cut: 18/20` and the reference head-word count is off in 11/20 (`Counter({0: 9, -1: 5, -2: 2, 2: 2, 1: 1, -3: 1})`), so the overall-WER reference is mis-ordered around a half-word; and the inserted B is a whole other-speaker, other-corpus sentence (`mean inserted-B duration s: 5.03`) — a sentence-level switch without a pause, not the intra-sentence switch the name and CLAUDE.md ("word-level EN↔UK within a sentence is not solved") refer to. *inter*: gaps are `{300: 8, 400: 7, 600: 5}` ms, `gaps < 500 ms: 15 of 20`, while `gmst-stream` in the eval uses `min_silence_ms=500` (run_eval.py:145) and `Config().min_silence_ms = 600` — so for the streaming path 3/4 of the "inter" (pause-separated) clips are never endpointed at the pause.
- [serious] `gmst bench`'s WER is not measured in the decoding mode GMST ships, and is one overall number where PLAN's exit criterion asks for UK WER and EN WER — `src/gmst/bench.py:91,95,102`; `PLAN.md:281`.
  Evidence: bench loads `per_segment_lid=False` and calls `engine.transcribe(audio, language=cfg.language)` with `language` default `None` (config.py:31) → `multilingual=language is None and not self._per_segment_lid` = True (faster_whisper.py:57): faster-whisper's own in-pass LID with no uk/ru tie-break. The stream path instead calls `engine.detect_language(...)` per utterance and then `engine.transcribe(audio, language=call_lang, ...)` (stream.py:115-119). A model whose LID mislabels uk as ru is penalised differently in the two modes, so bench's ranking is not the ranking for the shipped pipeline. PLAN.md:281: "`gmst bench` emits a table: (backend × model) → batch RTF, **streaming amplification**, **UK WER**, **EN WER**"; `BenchRow` has one `wer` field.
- [serious] `bench`'s streaming amplification is the formula PLAN defines (`RTF × max_buffer_seconds / 1 s`, bench.py:28,78,97; PLAN.md:130-136), but measurement contradicts that formula's premise that decode cost scales with `buffer_seconds`, and it omits the per-utterance LID pass — `scripts/R5/p4_amplification.py` (tiny, CPU int8, measured concurrently with R2's tiny probe).
  Evidence: batch RTF 0.0351 → bench amplification `0.527`; measured per-call wall time vs `RTF_batch*buffer_s`: `2 s: 0.421 vs 0.070 (6.0x)`, `4 s: 0.562 vs 0.141 (4.0x)`, `8 s: 0.562 vs 0.281 (2.0x)`, `15 s: 0.687 vs 0.527 (1.3x)`; `detect_language on 3 s: median 0.418 s`. Whisper pads each call to a 30 s window, so there is a large fixed per-update cost: in the trimmed regime PLAN relies on ("keeps `buffer_seconds` near one utterance"), the real per-update load is 4-6x what `RTF × buffer_seconds` predicts, and using the 15 s cap only happens to land near the truth. The quantity to report is measured wall time per decode of a buffer of typical length (plus LID) divided by `update_interval`. Needs repeating with large-* models / on the Mac (proposal X below).
- [serious] On the supported target the best-prior candidate is not benchmarked: `MLX_CANDIDATES` omits `Yehor/whisper-large-v3-turbo-quantized-uk`, which PLAN lists in the candidate set and the leaderboard ranks first (12.75 %) — `src/gmst/bench.py:37-41` vs `PLAN.md:68-69`.
  Evidence: `MLX_CANDIDATES = [("large-v2", ...), ("large-v3", ...), ("large-v3-turbo", ...)]`. Whether an mlx conversion exists is unknown (offline); either it must be converted or the Mac decision must be framed as "mlx large-v2 vs faster-whisper CPU turbo-uk".
- [minor] WER normalization handles casing, punctuation and apostrophes (ʼ / ’ / ' unify correctly) but not numerals or hyphenation, against references that are fully verbalised — `src/gmst/metrics.py:160-171`, `scripts/R5/p6_normalization.py`.
  Evidence: `reference rows containing a digit: 0 of 3204`; `ref='у тисяча дев'ятсот двадцятому році' hyp='у 1920 році' -> WER=0.60`; `ref='двадцять п'ять відсотків' hyp='25%' -> WER=1.00`; `ref='що-небудь' hyp='що небудь' -> WER=2.00` (82 hyphens in refs). This penalises base models (which write digits) relative to a CV-style fine-tune; whether the leaderboard normalizes the same way could not be checked offline. English side: LibriSpeech refs are also verbal and no Whisper English normalizer is applied.
- [minor] `run_eval --systems X` overwrites `eval/results/scores.json` with only X's scores, discarding the others' — `eval/run_eval.py:296-299` (`all_scores = [score(s) for s in (systems or _known_systems())]` then `write_text`). Use `--score-only` with no `--systems` to rebuild all.
