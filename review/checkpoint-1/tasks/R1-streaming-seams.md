# R1 — Streaming seams: reconcile, endpointer, stream loop, turns

## Instructions

Review line by line `src/gmst/reconcile.py`, `src/gmst/segment/endpointer.py`, `src/gmst/segment/turns.py` and `src/gmst/pipeline/stream.py` against the invariants in `CLAUDE.md` ("Streaming reconciliation") and `PLAN.md` ("`reconcile.py` edge cases", "`Segment` timestamp contract", the Ctrl-C and forced-commit rows of "Failure modes"). Read first: root `CLAUDE.md`, `PLAN.md`, `review/checkpoint-1/PLAN.md` (rules 1–8), this file. Set `status: done` before starting.

What counts as a finding: any input sequence that (a) commits a word twice, (b) makes committed spans non-monotonic, (c) re-commits a revised prefix, (d) loses text that was committed or was flushable at shutdown, (e) lets the real buffer grow past one utterance because the trim/rebase is skipped, or (f) writes to the sink from a thread other than the reconcile thread. Demonstrate each with a probe in `scripts/R1/` built on `tests/fakes.py` and the audio-reactive `_marked` / `_marked_engine` helpers in `tests/test_stream_pipeline.py` — a fixed script that ignores the audio it is handed cannot show a seam bug (CLAUDE.md "Testing"). Also check: the 600-character prompt cap, the 4000-word cap, the stall counter using the sample clock not wall time, and the second-Ctrl-C path.

## Findings

- [blocking] After every commit the trim leaves only a sliver of the last committed word in the buffer; when the model does not re-emit that exact word first (drops the sliver, or hears a different token), `_align` returns -1 on **every** later push of the utterance, nothing is committed or even shown as a partial, the buffer grows untrimmed, and at the endpoint `flush()` drops the whole unplaceable hypothesis while `ep.reset(keep_overlap=False)` discards its audio — so the "next decode will recover it" assumption (PLAN.md "Failure modes", CLAUDE.md "Streaming reconciliation") is false: there is no next decode of that audio. With a real model this loses ~85 % of the transcript. — `src/gmst/segment/endpointer.py:88` (`n = ... int((seconds - _TRIM_BACKOFF_S) * SAMPLE_RATE)` with `seconds` = the committed word's **end**, `src/gmst/pipeline/stream.py:183`), `src/gmst/reconcile.py:49-54` (anchor must match at `hyp[0]`), `src/gmst/reconcile.py:96-97` (flush drops), `src/gmst/pipeline/stream.py:151,164,173,176` (a contradicted push leaves `last_pending == []`, so `stalled` can never fire; `keep_overlap` is false, so the audio goes too).
  - Audio-reactive fake, shipped defaults (`scripts/R1/probe_trim_fragment.py`; two 6 s marked utterances, 24 words): `[faithful] ... lost 0/24` (the `_marked_engine` assumption), `[fragment] decodes=15 committed=3 biggest_decode=7.2s ... lost 21/24`, `[dropped] ... finals: w0 w1 w20 / lost 21/24`. `biggest_decode=7.2s` vs `2.2s` also shows (e): the trim is skipped for the whole contradicted utterance.
  - Real model, shipped defaults, silero VAD, 6 LibriSpeech clips from `eval/results/data/en` (81.2 s, 197 ref words) (`HF_HUB_OFFLINE=1 timeout 580 uv run python review/checkpoint-1/scripts/R1/probe_real_model_contradictions.py small 6`): `batch per-clip WER = 0.015`, `stream WER = 0.878 ... decodes=78 committed_words=24`, `counts: {'pushes': 78, 'contradicted': 63, 'flush_dropped_words': 174, 'flushes_dropping': 7}`; stream output `It was idle And the men of Israel And we have also There is no The crowd From rubbing shoulders with Cyril, there must`. `tiny`: batch 0.061, stream 0.873, 62/78 contradicted, first contradiction `committed tail ['idle'] | hyp head ['for', 'him', 'to', 'move', 'himself']` (the model dropped the 0.2 s sliver of "idle").
  - Attribution (tiny): not the prompt — with the prompt removed (`... tiny 6 noprompt`) stream WER 0.787, 59/78 contradicted, `committed tail ['idle'] | hyp head ['title', 'for', ...]` (sliver heard as "title"); not the back-off size — `backoff=0.6` gives stream WER 0.817, 58/78 contradicted, `committed tail ['him', 'to', 'move'] | hyp head ['himself', 'to', ...]`. The root cause is that `_align` only accepts an anchor that is an exact prefix of the new hypothesis, and every contradiction is terminal for the utterance.
  - Why the suite passes: `_marked_engine` (`tests/test_stream_pipeline.py:51-68`) decodes a 0.2 s sliver of a 0.5 s chunk as the full word, which no real model does; `tests/test_stream_realvad_slow.py:38` feeds Gaussian noise and asserts no content. The CLAUDE.md claim "verified end-to-end with real Silero VAD + tiny Whisper" (PLAN.md:283 "clean ordered transcript") does not survive real speech. Timings measured under concurrency (R2 `lid_probe.py tiny`, R5 probes running).
  - Also: the `trim_to` docstring says the cut "lands just before the word rather than inside it" (`endpointer.py:83-84`); it lands 0.2 s before the word's *end*, i.e. inside any word longer than 0.2 s.
- [serious] A second Ctrl-C that lands during an **in-loop** decode (the drain after the first Ctrl-C can hold up to `max_buffer_seconds` of queued audio) does not abandon the final decode: the `KeyboardInterrupt` unwinds the loop into `run_stream`'s `finally`, which starts the final decode anyway, now with SIGINT at `SIG_DFL`; a third Ctrl-C then kills the process without `sink.close()`, so an `--sink srt` session loses its whole file. CLAUDE.md: "A second Ctrl-C abandons the final decode instead of being ignored." — `src/gmst/cli.py:173-175`, `src/gmst/pipeline/stream.py:191-195`.
  - `HF_HUB_OFFLINE=1 uv run python review/checkpoint-1/scripts/R1/probe_second_ctrl_c.py`: `part1: KeyboardInterrupt propagated out of run_stream` / `part1: transcribe calls after the interrupt: 1 (buffer seconds each: [3.2]); sink.closed=True`; `part2: returncode=-2; finally ran (sink.close stand-in)=False`.
  - Also: the `KeyboardInterrupt` is not caught in `_cmd_stream` (only `DeviceLost` is, `cli.py:198`), so the second Ctrl-C ends in a traceback and skips the stats line; exit status is not the documented 0/2/3.
- [minor] The prompt cap's "~200 Whisper tokens" holds for neither language: Ukrainian 600 characters are 235 tokens (over faster-whisper's 223-token prompt window, which silently keeps the tail), and English is bound by the 100-word pre-cap at 511 characters / 126 tokens, so the character cap never applies to English. Harmless in effect (the truncation keeps the recent end) but the documented reasoning (CLAUDE.md, PLAN.md:163, `stream.py:41`) is off. — `src/gmst/pipeline/stream.py:41-42,118`; `HF_HUB_OFFLINE=1 uv run python review/checkpoint-1/scripts/R1/probe_prompt_tokens.py`: `en: prompt chars=511 words=100 tokens=126`, `uk: prompt chars=600 words=99 tokens=235`.
- [minor] A token that normalizes to empty (a standalone dash or ellipsis) can never agree (`if _norm(a) and ...`), so nothing after it commits until the stall counter force-flushes 3 decodes later (≥ 3 s at `min_chunk_seconds = 1.0`, the whole latency budget). Rare with faster-whisper word timestamps, which merge a leading "-" into the next word; more likely on the segment-text path (`word_timestamps = false`). — `src/gmst/reconcile.py:75`; `HF_HUB_OFFLINE=1 uv run python review/checkpoint-1/scripts/R1/probe_punct_token.py`: `1 (['Так'], ['-', 'звісно,', 'давайте', 'далі'])`, `2 ([], [...]) stalled_pushes = 1`, `3 ([], [...]) stalled_pushes = 2`.
