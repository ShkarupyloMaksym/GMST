## Findings

- [blocking] **F1 — `resolve_language` never restricts to the meeting's languages, so the stream decodes Ukrainian as `tr`, `ar`, `ru`, `bg`, `ja`… and emits text in that script.** Lead confirmed. `src/gmst/transcribe/lid.py:24-45` passes through any label the detector returns. The only rewrite is uk↔ru within `tiebreak_margin`. `stream.py:158-161` hands that label to `engine.transcribe(language=call_lang)`. `config.py:91` restricts `language` to `{en, uk}` for *pinning* only. Evidence from `lid_probe.py`, part A (full clip, `prev_lang=None`): tiny `resolved prev=None: {'ru': 27, 'uk': 21, 'pl': 4, 'bg': 2, 'ja': 2, 'cs': 2, 'ur': 1, 'hr': 1} -> not en/uk: 39/60`; small `-> not en/uk: 21/60`. Even with `prev_lang='uk'`, `ru` survives: tiny `{'uk': 47, 'ru': 13}`, small `{'uk': 48, 'ru': 12}` (e.g. `uk-3541 top3=[('ru', 0.972), ('uk', 0.012) ...]`, where the gap is far outside the 0.15 margin). Part C, the real `run_stream` path: tiny `languages handed to transcribe(): {'tr': 1, 'ru': 10, 'en': 1}; not en/uk: 11/12`, emitting `[tr] 'yorkot,navçidele,dobroho,tah'` and `[ru] 'университет,музыи и'`. small `[ar] 1.35-2.15 'يوركو'`, `[ar] 5.00-7.00 'موزيجي بيبليوتي'`.
- [blocking] **F2 — The sticky threshold does not protect the first utterance, and it then preserves a wrong first label.** `lid.py:39,43` only stays sticky `if ... prev_lang is not None`. `run_stream` starts with `prev_lang = language` = `None` (`stream.py:131`), so the meeting's first detection is accepted at any confidence and becomes the anchor that later low-confidence detections defer to. `lid_probe_small.out`: `LID on 2.00s prev=None raw=ar@0.21 ... -> used ar`, then `LID on 3.00s prev=ar raw=ru@0.423 ... -> used ar`. `lid_probe_tiny.out`: `prev=None raw=tr@0.435 -> used tr`, then a single `ru@0.708` (just over 0.7) locks `ru` for 9 of the next 10 utterances (`prev=ru raw=en@0.339 -> used ru`, `raw=es@0.317 -> used ru`, `raw=pl@0.306 -> used ru` …). The docstring's rationale ("switching an English meeting to `uk` on 0.11 confidence would then stick", `lid.py:12-14`) applies just as much to the first utterance, but no prior exists for it.
- [blocking] **F3 — In batch, "per-segment LID" only relabels. The text is faster-whisper's own first-window autodetect decode, with no tie-break, no sticky rule and no window. The labels can also contradict the script of the text.** `faster_whisper.py:54-57` calls `self._model.transcribe(language=None, multilingual=False)` when `per_segment_lid` is on. faster-whisper then detects once and decodes every segment in that language. `_detect_slice` (`:69`) only writes `Segment.language` afterwards. `mlx_whisper.py:53-66` has the same structure. `lid_probe_tiny.out` part B: `text identical to raw autodetect decode: 60/60; clips where GMST label != language the text was decoded in: 5/60`, e.g. `uk-259: decoded-as=cs gmst-labels=['ro'] text=' Štáraz o sím na hadejo.'` and `uk-2150: decoded-as=ru gmst-labels=['es'] text=' Уситок и вон есть.'`. Eval cross-check (gmst-batch vs fw-tiny-auto text): `uk-3726 True bg`, `uk-3519 True ja`, `uk-2023 True ru`, 11/12 identical. This is why `scores.json` gives gmst-batch UK WER = raw autodetect (68.21) and not the pinned 41.54. `eval/run_eval.py:6` describes `gmst-batch` as "per-utterance LID + tiebreak", so the eval that is meant to choose the model and default measures raw autodetect under GMST's name. That is a wrong-decision risk (rule 2).
- [serious] **F4 — The stream fixes an utterance's language from its first 1–4 s of buffer, not from the endpointed segment, and short prefixes of Ukrainian read as English.** `stream.py:157-158` detects once, when `utt_lang is None`, on the buffer at the utterance's first decode (`min_chunk_seconds=1.0`, `endpointer.py:65-66`). It keeps that answer until the endpoint. PLAN.md:40-41 says "detect language on each endpointed segment". Part C shows LID ran on 1.0–4.0 s buffers. Part A on the first 1.0 s of each uk clip: tiny `raw top-1: {'en': 38, 'ru': 13, 'nn': 4, ...}`, and with `prev=en` `{'en': 60}`; small `{'en': 42, ...}`, and with `prev=en` `{'en': 58, 'pt': 1, 'ru': 1}`. So in a mixed meeting, a Ukrainian utterance that follows English is decoded as English in 58–60 of 60 cases under this timing. That is the EN→UK switch the product exists for. On full clips, small with `prev=en` gives `{'uk': 27, 'en': 21, 'ru': 12}`. (This does not re-argue per-utterance LID. The implementation detects on a prefix, which the stated design does not say.)
- [serious] **F5 — The `mlx_whisper` dependency is not declared anywhere, and its import error escapes as a traceback.** `pyproject.toml:7-14` has no `mlx-whisper`, not as an extra and not as a `sys_platform == 'darwin'` marker, while CLAUDE.md/PLAN.md say "Pin the dep". So `uv sync` on the target Mac gives no fast path. `load_engine` wraps only `(OSError, ValueError)` (`backends/__init__.py:37`) and `_load_engine_or_report` catches only `ModelUnavailable, NotImplementedError` (`cli.py:29`). `model_unavailable_probe.out`: `mlx engine on linux: NOT wrapped -> builtins.ModuleNotFoundError: "No module named 'mlx_whisper'"`. A Mac without the package gets the same traceback, not exit 2.
- [serious] **F6 — `MlxWhisperEngine` loads nothing in `__init__`, so `load_engine` can never raise `ModelUnavailable` for it. An uncached or misspelled repo fails at the first `detect_language`/`transcribe` of the meeting, unwrapped. `gmst bench` also records ≈ 0 s load and folds the model load into the mlx RTF.** `mlx_whisper.py:36-41` stores only `self._repo`. Loading happens in `_load()` (`:120-125`) or inside `mlx_whisper.transcribe` (`:53`). In `run_stream` the exception propagates, and `_cmd_stream` catches only `DeviceLost` (`cli.py:198`). The failure-mode row "Model not cached … exits 2" (PLAN.md:158) is therefore unimplemented for the Mac backend. In `bench.py:89-95`, `row.load_seconds` times the lazy constructor, and the first `engine.transcribe` pays the full load (plus the download when online) inside `row.rtf` → `amplification`. That is the column that sets the Mac default. Found by reading only; the size of the effect is a Mac item.
- [minor] **F7 — The "run `gmst warmup`" hint is attached to failures that warmup cannot fix.** `backends/__init__.py:37-41` wraps every `ValueError`. `model_unavailable_probe.out`: `float16 on cpu: ModelUnavailable "could not load 'tiny': Requested float16 compute type, but the target device or backend do not support efficie" | hint='if the model is not cached yet, run: gmst warmup'`, and the same for `Invalid model size 'large-v9'`. The message text does say what went wrong, so the harm is small.
- [minor] **F8 — The docs say faster-whisper LID is in-pass and free, and the latency budget has no LID row for the portable default. The code runs a separate encoder pass per utterance.** `engine.py:5-6`: "LID is done in-pass (`multilingual=True`), so `detect_language` shares the decode work". PLAN.md:77-79 says the same and cites `language_detection_segments=1`, which the code never passes. PLAN.md:128 has `LID pass (mlx path only)`. The code calls `self._model.detect_language(audio)` (`faster_whisper.py:99`) once per utterance from `stream.py:158`, separate from the decode, and `multilingual` is `False` on every stream call because `language` is always set. PLAN.md:98 also shows `detect_language(self, audio)` without the `prev_lang` keyword that the Protocol (`engine.py:38-40`) and `stream.py:158` use.
